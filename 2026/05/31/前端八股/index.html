  • 从输入url到页面渲染完成有哪些步骤

    • 浏览器解析url，包括协议、域名、端口、路径、查询参数等等；如果不是完整url，会进行补全
    • 检查缓存：不会直接去请求服务器，而是先看本地是否有缓存
      • 强缓存：资源还在有效期内，浏览器直接从本地缓存读取，不发请求
      • 协商缓存：强缓存失败后，向服务器发送请求确认资源是否变化，如果资源没有变化，返回304 not modified，则继续使用本地缓存，否则返回新的资源内容
    • DNS解析：把域名解析为IP地址
    • 建立网络连接：拿到服务器IP后浏览器和服务器建立连接
      • HTTP: TCP三次握手
      • HTTPS是TCP三次握手和TLS握手：HTTPS比HTTP多了加密过程。TLS握手：确认服务器身份、协商加密算法、生成会话密钥、建立加密通信
    • 发送HTTP请求，POST\GET\DELETE\PUT
    • 服务器处理请求（匹配路由、读取静态文件、查询数据库、调用后端、生成HTML）然后返回HTTP响应（HTTP响应码
    • 浏览器拿到返回的HTML开始解析，被解析为DOM树，表示页面的结构
    • 遇到CSS资源就下载并解析CSS，生成CSSOM树（CSS会阻塞渲染，但是不阻塞DOM树构建
    • 遇到<script>，暂停HTML解析，下载JS，执行JS，然后再解析HTML。因为JS可能会修改DOM
      • defer：不阻塞HTML解析，等 DOM 解析完成后再执行。多个 defer 脚本按顺序执行，DOMContentLoaded 之前执行
      • async：不阻塞 HTML 解析，下载完马上执行，执行时会暂停 HTML 解析，多个 async 脚本执行顺序不确定
    • 构建渲染树Render Tree：将CSSOM树和DOM树合成渲染树，只包含需要显示的节点。例如（display：none不会显示在渲染树里面，但是visibility：hidden元素还是占位置会出现在渲染树中
    • 布局layout/reflow回旋：计算每个元素的位置和大小
    • 绘制
    • 合成Composite：不同图层合成显示
    • 继续加载其他资源：图片、字体、css文件、js文件、视频、接口数据
    • DOMContentLoaded：HTML解析完成，DOM树构建完成后触发；load：页面所有资源加载完成后触发

  • 浏览器缓存：F5刷新会跳过强缓存直接协商缓存，Ctrl+F5强制刷新会跳过协商缓存，直接重新请求资源

    • 强缓存：浏览器不向服务器发送请求，直接从本地缓存读取数据
      • 在浏览器解析完url获得服务器IP后请求资源，先判断强缓存是否有效，如果有效则使用，否则进入协商缓存
      • Cache-Control：max-age=3600，在3600s内可以直接使用缓存；如果是no-cache：意思是可以缓存，但是每次使用前必须先向服务器确认，也就是协商缓存；no-store：完全不缓存；pubilc：资源可以被浏览器缓存，也可以被代理服务器、CDN 缓存；private：表示资源只能被用户浏览器缓存，不能被代理服务器共享缓存。
      • expires：HTTP/1.0时代的字段，直接给出过期的具体时间，但是会依赖客户端本地的时间，所以如果本地时间不准，就会导致缓存判断出错
    • 协商缓存：浏览器会向服务器发送请求，询问服务器当前本地的这个缓存是否还能继续使用，如果没变则返回304 Not Modified，浏览器就继续使用本地缓存；否则返回200 OK，且返回新的资源内容
      • Last-Modified / If-Modified-Since：前者是服务器第一次返回资源携带，表示资源最后修改的时间。然后强缓存失效浏览器请求的时候会带上后者，表示本地缓存的资源的最后修改时间，便于服务器比较。但是last-modified的时间精度不够，以及如果内容没变但是修改时间变了会导致浏览器重新下载
      • ETag / If-None-Match：ETag是服务器给资源生成的唯一标识；浏览器在请求的时候就会在后者字段里面写入ETag用于比较
    • Memory Cache：内存缓存。速度更快，但是容量比较小，页面关闭后通常会释放
    • Disk Cache：磁盘缓存。速度比内存慢，容量更大，可以跨页面、跨浏览器会话保留
    • 在实际项目里面，一般HTML使用协商缓存，js、css图片等静态资源使用长期强缓存，但是会配备一个hash，当更新的时候html直接引用新的hash的文件，于是进行请求更新

  • TCP与UDP

    • 传输层协议
    • TCP全称Transmission Control Protocol传输控制协议，面向连接、可靠传输、按序到达。通信前先建立连接，通信过程中双方确认数据有没有收到，数据丢了会重传，最后再断开连接。类似打电话
      • 可靠传输：序列号、确认应答、超时重传、流量控制、拥塞控制
      • 保证有序，TCP会给数据编号
      • 慢启动、拥塞避免、快速重传、快速恢复
    • UDP全称User Datagram Protocol：用户数据报协议。无连接、不保证可靠、不保证顺序，但速度快、开销小。类似发短信。UDP的头部比TCP简单，开销小速度快，所以适用于对实时性要求较高，允许少量丢包的场景：视频直播、语音通话、在线游戏、DNS查询等
    • TCP传输字节流，没有天然的消息边界；而UDP是数据报，会保留消息边界
    • 三次握手与四次挥手：
      • TCP 通信前需要先建立连接，也就是经典的三次挥手——客户端发送 SYN；服务器返回 SYN + ACK；客户端返回 ACK
      • 三次挥手：确认双方发送和接收能力都正常，并同步初始序列号。
      • TCP 断开连接通常是四次挥手，因为 TCP 是全双工通信，双方都可以独立发送数据。要两边都发信号说自己要断开连接了，并且两边都说收到
    • TCP：HTTP/1.1、HTTP/2、HTTPS、WebSocket、文件传输、邮件、SSH、数据库连接

  • http状态码：服务器对客户端请求的处理结果

    • 按首位数字分为5类：1：表示信息响应，请求已收到继续处理；2：成功，请求成功处理；3：重定向，需要进一步操作，例如跳转或者使用缓存；4：客户端错误，请求有问题；5：服务端错误，指的是服务器处理出错
    • 1xx不是最终相应，是中间提示
    • 200 OK；201 Created；204 Not Content（请求成功但是没有响应体，DELETE）；
    • 301：Moved permanently，永久重定向，表示资源地址永久变化；302: Found，临时重定向；304 Not Modified，浏览器协商缓存的时候会出现；307 Temporary Redirect：临时重定向，保持原请求方法不变；308 Permanent Redirect：永久重定向，也要求保持原请求方法不变。
    • 400 Bad Request：请求格式有问题，服务器无法理解； 401 Unauthorized：未认证，可能是还没登录或者 token 无效；403 Forbidden：已经登录了但是没有权限；404 Not Found：资源不存在，例如访问了不存在路径；405 Method Not Allowed：请求方法不允许，例如只支持get但是发了post请求；408 Request Timeout。请求超时，表示客户端请求发送得太慢，服务器等不下去了；409 Conflict，请求冲突，常见于资源状态冲突。例如用户名已存在；413 Payload Too Large，请求体太大。比如上传文件超过服务器限制；429 Too Many Requests：请求太频繁被限流
    • 500 Internal Server Error：服务器内部错误，例如后端代码异常、数据库操作报错、后端服务崩了等等；502 Bad Gateway：网关错误，常见于Nginx作为反向代理的时候后端服务没有正常响应；503 Service Unavailable，服务暂时不可用；504 Gateway Timeout：网关超时。
